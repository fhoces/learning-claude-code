# Module 7 drill: hooks

In `~/claude-code-practice`. Needs `jq` (`brew install jq`).

## Q1. Protect the generated data

```bash
mkdir -p .claude/hooks
cat > .claude/hooks/protect-data.sh <<'SH'
#!/bin/bash
input=$(cat)
path=$(echo "$input" | jq -r '.tool_input.file_path // empty')
case "$path" in
  */data/trips.csv|data/trips.csv)
    echo "data/trips.csv is generated by data/build_data.R; edit the generator instead." >&2
    exit 2 ;;
esac
exit 0
SH
chmod +x .claude/hooks/protect-data.sh
cat > .claude/settings.json <<'JSON'
{
  "hooks": {
    "PreToolUse": [
      { "matcher": "Edit|Write",
        "hooks": [ { "type": "command",
                     "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/protect-data.sh",
                     "timeout": 10 } ] }
    ]
  }
}
JSON
```

Test by hand first:

```bash
jq -n '{tool_name:"Edit", tool_input:{file_path:"data/trips.csv"}}' | .claude/hooks/protect-data.sh; echo "exit $?"
jq -n '{tool_name:"Edit", tool_input:{file_path:"data/trip_metrics.R"}}' | .claude/hooks/protect-data.sh; echo "exit $?"
```

Expected: exit 2 with the message, then exit 0 silent. Now in a
session:

> /hooks

Expected: the hook listed under PreToolUse. Then:

> Change the first row of data/trips.csv so the rating is 4.

Expected: the edit is blocked, Claude sees the reason, and (if the
description did its job) offers to change the generator instead.

## Q2. Gate the push on a flag file

```bash
cat > .claude/hooks/gate-push.sh <<'SH'
#!/bin/bash
if [ -f .push-ok ]; then rm -f .push-ok; exit 0; fi
echo "No .push-ok flag. Run 'touch .push-ok' yourself to approve one push." >&2
exit 2
SH
chmod +x .claude/hooks/gate-push.sh
```

Add a second matcher group under `PreToolUse` in `.claude/settings.json`:

```json
{ "matcher": "Bash",
  "hooks": [ { "type": "command",
               "if": "Bash(git push *)",
               "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/gate-push.sh" } ] }
```

Add a throwaway remote so a push is possible without leaving the
machine:

```bash
git init -q --bare /tmp/practice-remote.git && git remote add origin /tmp/practice-remote.git
```

> Push main to origin.

Expected: blocked with the message. Then `touch .push-ok` yourself and
ask again: expected the push goes through and the flag is gone. A
second push without the flag is blocked again. This is module 1's
"push is its own approval step", enforced rather than remembered.

## Q3. Lint after every R edit

```bash
Rscript -e 'if (!requireNamespace("lintr", quietly=TRUE)) install.packages("lintr")'
cat > .claude/hooks/lint-r.sh <<'SH'
#!/bin/bash
input=$(cat)
path=$(echo "$input" | jq -r '.tool_input.file_path // empty')
case "$path" in
  *.R) out=$(Rscript -e "lintr::lint('$path')" 2>&1)
       if [ -n "$out" ]; then echo "$out" >&2; exit 2; fi ;;
esac
exit 0
SH
chmod +x .claude/hooks/lint-r.sh
```

Add under `PostToolUse` with matcher `Edit|Write`. Then:

> Add a line to data/trip_metrics.R that assigns x=1 with no spaces
> around the equals sign.

Expected: the edit lands (PostToolUse cannot block), the lint output
reaches Claude on stderr, and Claude fixes the spacing. Read the
transcript line.

## Q4. Prefilter a noisy command

Save the `filter-test-output.sh` from module 4's slide as
`.claude/hooks/filter.sh`, register it under `PreToolUse` / `Bash`,
and extend its pattern to `Rscript data/trip_metrics.R`. Ask Claude to
run the metrics script. Expected: in `claude --debug-file /tmp/hooks.log`
the log has a "modified tool input keys" line naming `command`, and
the output Claude sees is the filtered one.

## Q5. Context at session start

```bash
cat > .claude/hooks/session-start.sh <<'SH'
#!/bin/bash
echo "Branch: $(git branch --show-current). Last commit: $(git log -1 --format=%s)."
[ -f NEXT_SESSION.md ] && cat NEXT_SESSION.md
exit 0
SH
chmod +x .claude/hooks/session-start.sh
```

Register under `SessionStart` (no matcher). Write a two-line
`NEXT_SESSION.md`. Start a new session and ask "what did the last
session leave for you?" Expected: Claude quotes the note without
having been told to read it.

## Q6. Debug a hook that does nothing

Remove the executable bit from `protect-data.sh` and repeat Q1's edit.
Expected: the edit goes through; the transcript shows one dim line
about a hook error that is easy to miss. `claude --debug` shows the
failure in full. Restore with `chmod +x`. Then commit
`.claude/hooks/` and `.claude/settings.json`: they are the repo's
enforcement from now on, and a collaborator who trusts the workspace
gets them.
